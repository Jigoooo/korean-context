# Korean Context v0.1 설계

**상태:** 승인됨

**작성일:** 2026-09-03

**대상 저장소:** `Jigoooo/korean-context`

**릴리스:** `v0.1.0` 공개 프리릴리스

**라이선스:** MIT

## 1. 목적

Korean Context v0.1은 AI가 만드는 한국어 산출물이 해당 표면, 기술 분야, 독자, 문체에 맞는 표현을 사용하도록 돕는 Codex 중심의 공개 베타다. 전체 V1의 다중 에이전트 설치 시스템을 먼저 만들지 않고, 언어 정책과 플러그인 작동 여부를 실제 Codex 환경에서 검증하는 수직 슬라이스를 제공한다.

v0.1의 핵심 질문은 다음과 같다.

> 공유 한국어 작성 스킬을 Codex 플러그인으로 설치했을 때, 기술적 의미와 이미 자연스러운 표현을 보존하면서 부자연스러운 한국어 산출물을 일관되게 개선할 수 있는가?

## 2. 범위

### 포함

- Codex에서 설치 가능한 skills-only 플러그인
- `.codex-plugin/plugin.json` 기반 패키지
- 하나의 공유 언어 지식 원본
- 산출물 경계, 자연스러움, 번역투, 용어, 문체 정책
- 커밋, PR, 이슈, 리뷰, 주석, 문서, UI, 오류, 테스트, 릴리스 산출물 지침
- 일반 소프트웨어와 v0.1 핵심 보안 분야 지침
- 100개 평가 케이스와 스키마 검증
- 30개 대표 케이스의 실제 Codex 비교 실행
- 로컬 마켓플레이스 설치, 재설치, 제거 검증
- Windows 로컬 검증과 Windows/macOS/Linux CI
- 공개 GitHub 저장소 및 `v0.1.0` 프리릴리스
- 공개 플러그인 디렉터리 제출에 필요한 자료와 제출 시도

### 제외

- Claude Code 및 기타 에이전트 어댑터
- `npx korean-context@latest` 범용 설치 프로그램
- npm 배포
- 사용자 설정 파일을 수정하는 상시 활성화 브리지
- MCP 서버, 앱, UI, 훅
- 런타임 네트워크 요청
- 백그라운드 프로세스나 추가 모델 호출
- 자동 사용자 학습, 사용자별 교정 DB, 임베딩, 벡터 DB
- 데이터베이스, AI/ML, SOC, DFIR, 악성코드, 클라우드/IAM 심화 팩

v0.1은 전체 계획의 V1 또는 엄격한 Phase 0 통과를 주장하지 않는다. Codex에서 핵심 언어 정책과 플러그인 배포 경로를 먼저 검증하는 프리릴리스다.

## 3. 제품 동작

### 적용 경계

Korean Context는 다음처럼 저장되거나 게시될 한국어 산출물을 생성하거나 편집할 때만 적용한다.

- Git 커밋, PR, 이슈, 리뷰
- 코드 주석, JSDoc, docstring, TODO/FIXME
- README, 사양, 설계 문서, ADR
- 버튼, 레이블, 대화상자, 토스트, 유효성 검사, 오류 문구
- 테스트 이름과 설명, 변경 기록, 릴리스 노트

일반 대화, 진행 상황, 계획, 설명, 질문, 일반 기술 Q&A의 말투는 바꾸지 않는다. 한 응답에 대화와 산출물 초안이 함께 있으면 산출물 부분에만 정책을 적용한다.

### 우선순위

모든 판단은 다음 순서를 따른다.

```text
명시적 사용자 지시
> 기존 산출물 문체
> 프로젝트 관례
> 산출물 표면 지침
> 분야 지침
> Korean Context 기본값
```

### 생성 흐름

```text
한국어 산출물을 만들거나 고치는가?
  ├─ 아니요: 일반 동작 유지
  └─ 예
      ├─ 산출물 표면 식별
      ├─ 기술 분야 식별
      ├─ 기존 문체와 프로젝트 관례 확인
      ├─ 문체와 용어 선택
      ├─ 한 번에 작성
      └─ 같은 생성 안에서 짧게 의미·문체·자연스러움 확인
```

v0.1은 스킬의 명시적 호출과 설명 기반 암시적 호출을 모두 시험한다. 암시적 활성화는 베타 기능으로 표시하며, 안정적인 상시 활성화는 후속 릴리스에서 별도 브리지로 해결한다.

`plugins/korean-context/skills/korean-context/references`가 언어 지식의 유일한 원본이다. 평가 도구나 향후 어댑터는 이를 복사해 별도 정책으로 유지하지 않고 이 경로를 참조한다.

### 플러그인 매니페스트

`plugin.json`은 다음 원칙을 따른다.

- 이름: `korean-context`
- 버전: `0.1.0`
- 작성자: `김지우`
- 저장소 및 홈페이지: `https://github.com/Jigoooo/korean-context`
- 라이선스: `MIT`
- 스킬 경로: `./skills/`
- 분류: `Productivity`
- MCP, 앱, 훅 필드는 포함하지 않음
- 웹사이트, 개인정보 처리방침, 이용약관은 공개 저장소 문서 URL 사용
- 실제 파일로 존재하는 로고와 아이콘만 선언
- 기본 프롬프트는 최대 3개이며 128자보다 짧게 유지

repo marketplace는 `./plugins/korean-context`를 가리킨다. 로컬 시험에서는 이 저장소 루트를 Codex 로컬 마켓플레이스로 등록하고 해당 항목으로 설치한다. 플러그인 제작 도구로 marketplace 파일을 생성하며 설정 파일을 수동 편집하지 않는다.

## 5. 언어 지식 구성

### 스킬 진입점

`SKILL.md`는 다음 역할만 맡는다.

- 적용/비적용 조건 판정
- 표면, 분야, 문체 선택 순서
- 필요한 참조만 읽는 라우팅
- 의미 보존 및 기존 문체 우선 규칙
- 같은 생성 안에서 수행하는 짧은 최종 확인

세부 예시와 용어 목록은 진입점에 넣지 않는다. 스킬 설명은 산출물 작성 요청에는 잘 활성화되고 일반 대화에는 활성화되지 않도록 긍정·부정 트리거를 함께 명시한다.

### 핵심 참조

- `core-naturalness.md`

- `core-terminology.md`
- `core-register.md`

### 표면 참조

## 6. 평가 설계

### 100개 평가 코퍼스

평가 케이스는 다음 분포를 정확히 지킨다.

| 유형                         | 개수 |
| ---------------------------- | ---: |
| 부자연스러운 표현 개선       |   45 |
| 맥락으로부터 산출물 생성     |   15 |
| 이미 자연스러운 표현 보존    |   10 |
| 기존 문체/프로젝트 관례 충돌 |   10 |
| 처음 보는 표현으로 규칙 전이 |   10 |
| 일반 대화 비적용 경계        |   10 |
| 합계                         |  100 |

각 케이스는 고유 ID, 유형, 표면, 분야, 입력, 기대 행동, 금지 행동, 보존해야 할 식별자/숫자/코드, 평가 메모를 가진다. 자동 검증기는 총개수, 유형별 개수, ID 중복, 필수 필드, 허용 enum, 보호 토큰을 검사한다.

### 실제 Codex 비교 실행

100개 중 30개를 고정된 대표 세트로 지정한다.

| 유형 | 개수 |
| ---- | ---: |
| 개선 |   10 |
| 생성 |    5 |
| 보존 |    5 |
| 충돌 |    3 |
| 전이 |    3 |
| 경계 |    4 |

가능하면 동일한 Codex 모델과 추론 설정으로 다음을 각각 새 실행에서 수행한다.

1. 플러그인 없는 기준선
2. 플러그인 설치 후 명시적 호출
3. 플러그인 설치 후 암시적 활성화

결과에는 실행 날짜, Codex 버전, 모델, 추론 설정, 프롬프트, 원문 출력, 점수, 실패 이유를 기록한다. 모델이나 실행 설정을 고정할 수 없으면 차이를 결과 문서에 명시하고 직접 비교 주장을 제한한다.

### 점수

각 산출물은 다음 항목을 0~2점으로 평가한다.

- 자연스러움
- 용어 정확성
- 의미 보존
- 산출물 적합성
- 번역투 억제

총점은 10점이다. 경계 케이스는 정책이 일반 대화에 개입했는지를 별도로 판정한다.

### v0.1 릴리스 게이트

- 플러그인 구조 및 매니페스트 검증 통과
- 스킬 구조 및 frontmatter 검증 통과
- 100개 평가 스키마와 분포 검증 통과
- 30개 대표 케이스가 세 실행 모드에서 모두 완료
- 기술적 의미 훼손 0건
- 심각한 기술 용어 오역 0건
- 경계 위반 0건
- 보존 케이스의 불필요한 수정 1건 이하
- 개선 케이스 10개 중 9개 이상 개선
- 전이 케이스 3개 모두 의도한 원칙 적용
- 산출물 케이스 평균 8.5/10 이상
- 설치, 동일 버전 재설치, 개발 버전 갱신, 제거 검증 통과

하나라도 실패하면 GitHub 릴리스와 공개 디렉터리 제출을 중단하고 실패 결과를 저장한 뒤 규칙 또는 패키징을 수정한다.

## 7. 자동화와 CI

개발 도구는 Node.js 20 이상, TypeScript, pnpm을 사용한다. 플러그인 자체는 런타임 코드를 실행하지 않는다.

CI는 Windows, macOS, Linux에서 다음을 수행한다.

- 포맷 및 lint
- TypeScript typecheck
- 단위 테스트
- 평가 스키마 및 정확한 분포 검증
- 참조 경로와 보호 토큰 검증
- 플러그인 매니페스트 검증
- 스킬 검증
- 배포 번들에 선언되지 않은 파일이나 누락된 자산이 없는지 검사

실제 모델 비교 실행은 비용과 계정 인증이 필요한 수동 릴리스 게이트로 유지한다. 결과 파일은 개인 정보와 자격 증명을 포함하지 않으며 원본 소스 코드가 필요한 케이스는 합성 fixture만 사용한다.

## 8. 오류 처리와 안전

- 깨진 참조 경로, 잘못된 매니페스트, 중복 평가 ID는 즉시 실패 처리한다.
- 평가 실행이 중단되면 완료된 결과와 실패 지점을 보존하고 통과로 간주하지 않는다.
- 플러그인 설치 테스트는 관리 대상 플러그인과 마켓플레이스 항목만 변경한다.
- 기존 Codex 마켓플레이스와 다른 플러그인 설치 항목을 보존한다.
- 개발 갱신은 버전 번호를 반복해서 올리지 않고 Codex cachebuster 절차를 사용한다.
- 비밀, 토큰, 전체 사용자 설정 내용은 로그나 저장소에 기록하지 않는다.
- 제거 테스트는 Korean Context가 소유한 항목만 제거했는지 확인한다.

## 9. 배포 흐름

1. 로컬 플러그인 및 repo marketplace 항목 생성
2. 정적 검증과 단위 테스트 실행
3. 저장소 마켓플레이스를 등록하고 해당 소스에서 설치
4. 새 Codex 실행으로 30개 대표 세트 비교
5. 설치·재설치·갱신·제거 수명주기 검증
6. 전체 릴리스 게이트 재검증
7. `Jigoooo/korean-context` 공개 저장소 생성 및 `main` 푸시
8. `v0.1.0` 태그와 GitHub prerelease 생성
9. README의 설치 및 알려진 제한 검증
10. 공개 플러그인 디렉터리 제출 자료 준비 및 제출

공개 디렉터리 제출에는 OpenAI Platform의 Apps Management 쓰기 권한과 검증된 개발자 또는 사업자 신원이 필요하다. 또한 이름, 설명, 로고, 웹사이트, 지원 URL, 개인정보 처리방침, 이용약관, 시작 프롬프트, 긍정 테스트 5개, 부정 테스트 3개, 배포 지역, 릴리스 노트를 제출한다. 계정 권한이나 신원 검증이 준비되지 않았다면 GitHub 프리릴리스까지 완료하고, 제출 단계만 외부 차단 사항으로 정확히 보고한다. 심사 승인과 공개 시점은 외부 절차이므로 완료를 보장하지 않는다.

## 10. 문서와 공개 약속

README 첫 화면은 다음을 명확히 전달한다.

- Korean Context는 AI가 만드는 한국어 산출물을 위한 도구다.
- 일반 대화 말투를 바꾸는 도구가 아니다.
- v0.1은 Codex 중심 프리릴리스다.
- 자동 학습, 산출물 업로드, 백그라운드 모델, 런타임 네트워크가 없다.
- 명시적 호출이 가장 신뢰할 수 있고 암시적 활성화는 베타다.
- 검증한 환경과 날짜만 지원 정보로 표시한다.

`PRIVACY.md`와 `TERMS.md`는 skills-only 로컬 처리라는 실제 동작을 설명한다. 존재하지 않는 서비스, 보증, 수집 항목을 주장하지 않는다.

## 11. 후속 릴리스 경로

- `v0.2`: Codex 상시 활성화 브리지 검증, Claude Code 어댑터, 엄격한 Phase 0 비교
- `v0.3+`: 데이터베이스·AI/ML·보안 심화 팩, 추가 에이전트 조사
- `v1.0`: `npx korean-context@latest` 범용 설치기, 검증된 다중 에이전트 지원, npm 및 전체 V1 릴리스

후속 범위는 v0.1 결과와 실패 데이터를 근거로 조정한다. v0.1에서 검증되지 않은 에이전트나 기능을 지원한다고 표시하지 않는다.

## 12. 완료 기준

v0.1은 다음 조건을 모두 만족할 때 완료다.

- 승인된 구조와 범위가 구현됨
- 모든 자동 검증과 CI가 통과함
- 실제 Codex 비교 결과가 릴리스 게이트를 통과함
- 로컬 설치 수명주기가 검증됨
- 공개 저장소와 GitHub 프리릴리스가 존재함
- 제출 조건이 충족되면 공개 플러그인 디렉터리에 제출됨
- 제출 조건이 충족되지 않으면 필요한 사용자 조치와 현재 상태가 문서화됨
- 전체 V1로 오인할 표현이 없음
