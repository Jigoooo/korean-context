# Register

## Purpose

산출물의 독자와 기존 관례에 맞는 문체를 일관되게 사용한다.

## Rules

우선순위는 명시적 지시, 기존 산출물, 프로젝트 관례, 표면 기본값 순이다.

- 해요체: 협업 리뷰, 사용자에게 설명하는 UI와 오류
- 합니다체: PR 본문, 이슈, 공개 릴리스 안내
- 한다체: 기술 문서, 설계 문서, 코드 주석
- phrase: 커밋 제목, 짧은 레이블, 변경 기록 항목

기능적 이유 없이 한 산출물 안에서 문체를 섞지 않는다. 기본값은 새 산출물에만 적용한다.

## Counterexamples

- 기존 PR이 모두 한다체면 기본 합니다체보다 기존 스타일을 따른다.
- 제품 전체가 합니다체면 UI 오류도 그 보이스를 유지한다.
- 버튼 `저장`을 완전한 문장으로 늘리지 않는다.

## Same-generation check

문장 종결과 높임 수준이 일관되는지, 기존 관례를 기본값으로 덮지 않았는지 확인한다.
