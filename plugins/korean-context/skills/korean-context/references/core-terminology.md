# Terminology

## Purpose

분야, 표면, 독자에 따라 통용되는 기술 용어를 선택하고 식별 가능한 표기를 보존한다.

## Rules

- 용어 형태는 `preferred`, `accepted`, `contextual`, `avoid`로 판단한다.
- 영문을 피하려고 낯선 한국어를 만들지 않고, 원문이 영문이라는 이유만으로 그대로 두지도 않는다.
- 영문 코드 식별자는 익숙한 한국어 음역이 있어도 글자 단위로 보존한다. 명시적인 프로젝트 매핑이나 사용자 요청이 없으면 번역하지 않는다.
- API, SDK, CLI, CVE, 함수명, 옵션, 코드, URL, 버전, 숫자는 정확히 보존한다.
- 고유 표기와 식별자는 글자 단위로 보존하고 앞뒤에 다른 영문이나 숫자를 붙이지 않는다.
- 요청 범위를 정하는 버전, 명령어, 식별자는 다른 형식으로 정리하더라도 결과에서 누락하지 않는다.
- 약어가 통용되면 유지한다. 첫 등장에서 독자에게 필요할 때만 한국어를 병기한다.
- 프로젝트 용어집과 기존 산출물 표기가 기본값보다 우선한다.
- 프로젝트가 정한 용어는 일반 영문 표현이나 익숙한 동의어로 되돌리지 않는다.
- 프로젝트가 특정 개념에 정한 용어는 같은 문장 안의 일반 동의어에도 적용한다. 맥락상 grid cell인 대상을 일반 `위치`로 남기지 않는다.
- 프로젝트 용어를 요구한 산출물은 작성 전에 preferred와 forbidden 표현을 확인하고, 작성 후 preferred 개념이 남고 forbidden 표현이 없는지 한 번 더 검사한다.
- prompt에 용어 매핑이 없고 요청이 workspace와 연결되어 있으면 초안을 쓰기 전에 아래 순서로 확인한다.
  1. `<workspace>`는 현재 workspace root로 해석한다.
  2. `vocabulary`, `terminology`, `glossary`, `wording`, `용어`, `어휘`, `SSOT` 이름의 원본을 파일명부터 찾는다.
  3. 가장 작고 명시적인 원본에서 필요한 preferred와 forbidden 표현을 읽는다.
  4. 원본의 매핑을 적용한 뒤에만 산출물을 작성한다.
- 코드와 로그의 빈도만으로 관례를 추정하지 않는다.
- 용어 하나를 문서 전체에서 기계적으로 치환하지 않는다.

## Counterexamples

- `fallback`을 무조건 `후퇴 경로`로 번역하지 않는다.
- 보안 실무에서는 `Lateral Movement`와 `측면 이동`이 독자와 문맥에 따라 모두 가능하다.
- `mitigation`과 `remediation`은 문맥상 완화와 근본 수정의 차이를 보존한다.

## Same-generation check

식별자와 수치가 그대로인지, 선택한 용어가 같은 개념을 가리키는지 확인한다.
