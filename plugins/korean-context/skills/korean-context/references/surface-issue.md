# Issue

## Audience

문제를 재현하고 해결할 사람.

## Default register

합니다체. 짧은 template은 phrase를 유지한다.

## Rules

- 환경, 재현 절차, 실제 결과, 기대 결과를 분리한다.
- 관찰하지 않은 원인을 단정하지 않는다.
- 제공되지 않은 계정 상태, 버전, 단계, 오류 메시지는 만들지 않는다. 정보가 부족하면 알려진 사실만 bullet로 쓴다.
- 사용자가 말한 프로젝트 형식과 알려진 사실은 충분한 맥락으로 취급한다.
- 이 맥락만으로 요청한 항목을 쓸 수 있으면 바로 산출물을 반환하고 템플릿 파일을 확인하거나 추가 자료를 요청하지 않는다.
- 한 항목을 요청하면 `- <항목>: <알려진 사실>` 형태로 쓴다.

## Avoid

`현상이 발생합니다`의 반복, 가짜 stack trace, 해결책으로 가장한 추측.
빈 placeholder, 대괄호 안내, 값이 없는 colon을 추가하지 않는다.

## Examples

- `Windows에서 빈 config.json으로 시작하면 앱이 종료됩니다.`
- `- 재현 조건: 로그인 실패`
